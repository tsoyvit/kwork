# Kwork Research

Практическая исследовательская база по запуску и масштабированию профиля разработчика на Kwork.

## Цель

Максимизировать количество успешно выполненных оплачиваемых IT-заказов, положительных отзывов и выручку за минимально возможное время. Профиль не ограничивается одной технологией или нишей; отдельные кворки должны соответствовать конкретным покупательским задачам.

## Принцип исследования

Сначала собираются наблюдаемые данные из реального интерфейса Kwork, затем выделяются повторяющиеся паттерны. Факты, выводы и гипотезы не смешиваются. Конкуренция не используется как причина отказываться от услуги: она рассматривается только как контекст для упаковки, цены и порядка действий.

## Текущий объём

Срез 2026-08-10 через авторизованную браузерную сессию Kwork:

- **421 карточка** в **18 сегментах**;
- **22 сильных продавца** с отдельными кейсами;
- **14 deep-dives** конкретных карточек;
- живой срез Биржи проектов с buyer/hire/proposals/budget metrics;
- отдельные спецификации карточки, профиля, портфолио и отклика;
- стартовая матрица из 20 кворков и вторая волна ещё из 20.

## Основной вывод на текущем объёме данных

Расширение выборки не опровергло первоначальную модель. Наоборот, она стала устойчивее:

**широкий технический профиль → много узких покупательских входов → дешёвые микро-заказы для acquisition + средние системные задачи + отдельные high-ticket продукты.**

На уровне карточки главное правило остаётся тем же:

**один кворк = одна понятная причина покупки.**

Новые сегменты дополнительно подтвердили, что самостоятельными buyer intents являются не только разработка и исправления, но и PageSpeed, Excel/VBA, Google Sheets, QA, deploy/setup, плагины, консультации и конкретные AI-бизнес-функции.

## Следующий этап

Рынок уже исследован достаточно широко, чтобы смещать приоритет с competitor research на запуск:

1. подготовить финальные тексты первых 10–20 карточек;
2. подготовить cover briefs и portfolio proof;
3. завершить seller onboarding;
4. публиковать кворки и параллельно работать с Биржей;
5. собирать собственные conversion data;
6. обновлять спецификации и стратегию по фактическим заказам.
