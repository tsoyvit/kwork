# Cover Briefs — Wave 1

Цель: обложка должна быть понятна в маленькой карточке Kwork за 1–2 секунды. Не перегружать логотипами и мелким текстом.

## Общие правила

- один главный тезис;
- 2–5 слов крупно;
- secondary line максимум 3–4 коротких маркера;
- визуал = symptom / result / product, а не абстрактный «код»;
- для micro-services лучше literal problem/outcome;
- для high-ticket — реальный интерфейс или product modules;
- использовать единый визуальный язык, чтобы карточки узнавались как одна витрина.

## Визуальные семейства

### Family A — проблемы/ремонт
Для 1–4, 7, 8, 12, 15.

Композиция:
`симптом крупно → короткий technical marker → visual proof/check`.

### Family B — data flows
Для 5, 10, 11, 13, 14, 17, 19.

Композиция:
`SOURCE → RESULT`.

Стрелка — важный buyer signal: клиент понимает, что системы будут связаны.

### Family C — продукты
Для 16, 18, 20.

Композиция:
- реальный interface/product visual;
- крупное название продукта;
- 3–4 modules максимум.

## Что подготовить для дизайна

1. фотография автора — для части expert/high-ticket covers, если будем использовать;
2. Skillcue screenshots;
3. RuviCRM screenshots;
4. Telegram bot screenshots;
5. anonymized CRM/interface screenshots или mockups;
6. spreadsheet/parser demo outputs.

## A/B гипотеза после запуска

После появления impressions/views тестировать не «красивее/некрасивее», а:
- problem text vs outcome text;
- screenshot vs illustrated flow;
- face vs no face для high-ticket;
- generic technology logo vs concrete result.

Не менять одновременно title, price и cover — иначе невозможно понять причину изменения конверсии.
