# Kwork Launch Checklist

Цель: перейти от research к реальному запуску без ожидания «идеальной упаковки».

## Этап 1 — аккаунт

- [ ] Завершить seller onboarding `Стать продавцом`.
- [ ] Поставить нормальную фотографию вместо `T`.
- [ ] Перенести title/description из `launch/profile/FINAL_PROFILE.md`.
- [ ] Выбрать максимально широкий релевантный набор skills из доступных Kwork.
- [ ] Проверить, как профиль выглядит публично с desktop и mobile.

## Этап 2 — стартовое портфолио

- [ ] Подготовить main screenshot Skillcue.
- [ ] Подготовить Skillcue admin/user cabinet screenshots.
- [ ] Подготовить screenshot Windows app.
- [ ] Подготовить RuviCRM calendar/CRM screenshots.
- [ ] Нарисовать чистую схему API/webhook integration.
- [ ] Подготовить site → CRM visual.
- [ ] Выбрать реальный Telegram bot и сделать 2–4 screenshots.
- [ ] Проверить, что на screenshots нет секретов, персональных данных и приватных client data.
- [ ] Собрать минимум 5 сильных portfolio items по `launch/portfolio/PORTFOLIO_PLAN_V1.md`.

## Этап 3 — первые кворки

Источник готовых текстов:
- `launch/kworks/WAVE1_READY_01_10.md`;
- `launch/kworks/WAVE1_READY_11_20.md`.

### Публиковать сначала

- [ ] WordPress правки.
- [ ] HTML/CSS/JS/PHP fix.
- [ ] PHP / Error 500.
- [ ] Верстка/mobile fix.
- [ ] Site → Telegram.
- [ ] WordPress plugin/theme.
- [ ] Bitrix доработка.
- [ ] Laravel/backend fix.
- [ ] Python script.
- [ ] Parser → Excel.

### Затем

- [ ] Excel/Sheets automation.
- [ ] VPS/Linux/Nginx/SSL.
- [ ] API/webhook.
- [ ] CRM integration.
- [ ] Telegram bot fix.
- [ ] Simple Telegram/MAX bot.
- [ ] n8n/Make/Zapier.
- [ ] Business Telegram bot.
- [ ] AI/LLM integration.
- [ ] MVP/SaaS/admin panel.

## Для каждого кворка перед кнопкой «Опубликовать»

- [ ] Title описывает buyer intent, а не профессию.
- [ ] Base price соответствует base scope.
- [ ] Scope измеримый: 1 проблема / 1 форма / 1 endpoint / 1 workflow / etc.
- [ ] В description понятно, что получит заказчик.
- [ ] Указано, что не входит в base, если есть риск scope creep.
- [ ] Добавлены 3–7 логичных extras.
- [ ] Requirements минимальны и достаточны.
- [ ] Cover читается в thumbnail.
- [ ] Portfolio proof релевантен к intent.
- [ ] Нет неподтверждённых цифр/результатов.

## Этап 4 — Биржа одновременно с публикацией

- [ ] Не ждать органических заказов.
- [ ] Открыть Биржу сразу после seller onboarding.
- [ ] Отвечать на весь технически выполнимый поток в порядке приоритета.
- [ ] Не отбрасывать проект только из-за большого числа предложений.
- [ ] В первую очередь отвечать на понятные задачи с быстрым delivery и сильным matching case.
- [ ] Для microtask не писать длинное КП.
- [ ] Фиксировать цену/scope до начала работы.

## Этап 5 — после каждого заказа

- [ ] Выполнить раньше заявленного срока, если возможно без риска качества.
- [ ] Проверить работу перед сдачей.
- [ ] Сформулировать сдачу через результат, а не список технических действий.
- [ ] Попросить заказчика проверить результат.
- [ ] После успешной сдачи корректно напомнить об отзыве, если это уместно в интерфейсе/правилах Kwork.
- [ ] Добавить anonymized screenshot/before-after в portfolio, если возможно.
- [ ] Записать реальную трудоёмкость заказа.
- [ ] Обновить base scope/extras, если оценка была неточной.
- [ ] Создать идеи соседних кворков из реального заказа.

## Этап 6 — ежедневные метрики

- [ ] Сколько проектов Биржи просмотрено.
- [ ] Сколько релевантных откликов отправлено.
- [ ] Median response time.
- [ ] Ответы заказчиков.
- [ ] Активные диалоги.
- [ ] Заказы.
- [ ] Выручка.
- [ ] Выполненные заказы.
- [ ] Отзывы.
- [ ] Повторные заказы.

## Этап 7 — после первого успешного заказа

- [ ] Проверить новый доступный лимит кворков.
- [ ] Не останавливаться на 20 карточках.
- [ ] Начать Wave 2 из `strategy/second-wave-20-kworks.md`.
- [ ] Раскладывать каждый сильный execution skill на отдельные buyer intents.
- [ ] Добавить новые portfolio proofs из выполненных заказов.

## Что пока НЕ автоматизировать

- [ ] Не делать массовый scraper Kwork.
- [ ] Не делать безнадзорный автоотклик.
- [ ] Не совершать действия от аккаунта без контроля.

## Что автоматизировать первым

- [ ] Хранилище portfolio cases.
- [ ] Классификацию проекта.
- [ ] Подбор подходящего case.
- [ ] Draft отклика.
- [ ] Оценочный checklist scope/risks.
- [ ] Telegram-уведомление с готовым draft для ручной проверки.

# Definition of Done первого запуска

Старт считается выполненным, когда:
- профиль публично заполнен;
- есть минимум 5 portfolio proofs;
- опубликованы 20 стартовых кворков либо максимально доступное количество;
- отправлены первые релевантные отклики на Бирже;
- начат учёт funnel metrics.
