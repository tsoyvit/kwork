# Что нужно собрать у владельца профиля для финальной публикации

Без этих материалов тексты уже можно готовить, но portfolio/covers будут слабее.

## 1. Аватар

Нужна 1–3 фотографии:
- лицо крупно;
- нормальный свет;
- нейтральный фон;
- без сильной обработки.

## 2. Skillcue

Нужны screenshots без секретов и персональных данных:
- главный пользовательский экран;
- admin panel;
- Windows application;
- realtime/chat;
- при наличии — landing/product overview.

## 3. RuviCRM

Нужны:
- расписание/календарь;
- список/карточка клиентов;
- сотрудники;
- услуги;
- online booking/admin flow.

## 4. Telegram

Выбрать 1–2 самых сильных реально работающих бота и дать:
- screenshot диалога/menu;
- основной workflow;
- admin/interface при наличии;
- кратко: какую задачу решает, какие integrations есть.

## 5. Rubikon

Для публичного портфолио нужны только материалы, которые допустимо показывать.

Если клиентские screenshots использовать нельзя, достаточно подтвердить, какие из следующих flows можно описывать публично:
- CRM ↔ YCLIENTS/Altegio;
- site/form → amoCRM;
- API/webhook integration;
- GetCourse / МойСклад / Tilda / hh.ru / Avito / другие integrations;
- CRM analytics/widgets.

Для закрытых систем будем делать anonymized diagrams вместо клиентских screenshot.

## 6. Старые micro-projects

Если сохранились любые небольшие работы, особенно полезны:
- WordPress fixes;
- site forms;
- parser outputs;
- Excel/CSV automation;
- server/deploy;
- PHP/JS fixes.

Даже 1–2 screenshot before/after дают более релевантный proof для дешёвых micro-kworks, чем крупный SaaS-case.

# Формат передачи

Не нужно писать длинное описание каждого проекта.

Достаточно для каждого материала:

`название/что это → screenshot(s) → что пользователь делает → что было реализовано → можно ли показывать публично`.
