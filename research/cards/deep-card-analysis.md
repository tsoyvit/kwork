Дата живого просмотра: 2026-08-10.

Цель этого файла — не перечислить карточки, а понять **как сильные продавцы превращают услугу в товар**: title, cover, базовый scope, extras, требования и ценовую лестницу.

# Сводная формула карточки, которая вытекает из реальных примеров

## Title

Один из четырёх типов:

1. **Problem** — `Ошибка 500 WordPress`.
2. **Outcome** — `Парсер сайтов → Excel/CSV`.
3. **Product** — `Telegram bot + CRM/API/payment`.
4. **Platform + job** — `Доработка WordPress`, `Настройка VPS`, `WB API → Google Sheets`.

Не обязательно всегда называть стек.

## Cover

Сильные варианты в исследованной выборке:

- огромная проблема/результат текстом;
- screenshot конечного артефакта;
- лицо + короткий оффер;
- platform logo + job;
- high-ticket: список ключевых модулей/функций.

Общее правило: **прочитываться за 1–2 секунды в уменьшенной карточке**.

## Base scope

Обязательно ограничивается измеримой единицей:
- до 3 правок;
- 1 calculator / до 4 параметров;
- 1 site;
- 1 workflow;
- 1 problem / X time;
- 1 000 SKUs / 1 month;
- basic bot logic.

## Extras

Самые повторяемые механизмы upsell:

- срочность;
- deploy/install;
- API integration;
- DB;
- admin panel;
- styling/layout;
- emails/Telegram notifications;
- file/image handling;
- authorization;
- extra volume/parameters;
- additional time;
- support/maintenance.

## Requirements

Хороший seller снижает риск до заказа и просит только то, что нужно для старта:
- краткое описание результата;
- reference/example;
- URL/source;
- access;
- API keys;
- input/output fields;
- formula/business rules.

## Description

У сильных карточек оно выполняет 4 функции:

1. подтверждает, что продавец понял класс задачи;
2. перечисляет, что именно умеет решить;
3. ограничивает базовый scope;
4. сообщает, что нужно от клиента.

Длинный технический CV внутри карточки для этого не требуется.
