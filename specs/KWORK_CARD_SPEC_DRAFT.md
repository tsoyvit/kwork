# KWORK_CARD_SPEC — draft 0.1

Статус: **черновая спецификация**, основанная на первом живом срезе Kwork. Будет уточняться после анализа дополнительных сегментов, обложек, extras и свежих отзывов.

## Главный принцип

**Один кворк = одно понятное покупательское намерение.**

Профиль может быть широким, но карточка должна отвечать на конкретный запрос клиента.

Плохо:

> Full Stack разработка любой сложности

Лучше:

> Доработаю сайт на WordPress

> Исправлю PHP / JavaScript ошибки на сайте

> Настрою уведомления с сайта в Telegram

> Доработаю автоматизацию n8n

> Напишу парсер сайта с выгрузкой в Excel / CSV

---

## 1. Название

### Формулы, которые уже наблюдаются у сильных карточек

1. **Действие + объект**
   - Доработаю сайт на WordPress
   - Настрою сайт на CMS WordPress
   - Восстановлю сайт

2. **Результат + технология/среда**
   - PHP, JavaScript, Laravel — доработка или правки сайтов
   - AI агент и LLM GPT интеграция в ваш проект

3. **Конкретная бизнес-функция**
   - AI-агент для заявок, CRM, продаж и поддержки
   - Автопостинг из Telegram в TikTok, YouTube, VK

4. **Продуктовый результат**
   - Ипотечный калькулятор с диаграммой и таблицей платежей
   - Telegram-бот под бизнес: логика, оплата, CRM, API

### Требование

Название должно позволять клиенту за 1–2 секунды понять:
- что будет сделано;
- для какого объекта/сервиса;
- какой результат он получит.

---

## 2. Цена входа

Первый срез показывает, что даже сильные продавцы с 1K–3K+ отзывов используют входные цены 500–1 000 ₽ для конкретных небольших задач.

Следовательно, для нового профиля допустима лестница:

- **микрокворк:** 500–1 500 ₽;
- **средняя доработка:** 2 000–7 000 ₽;
- **продукт/интеграция:** 7 000–30 000+ ₽;
- **сложная автоматизация / система:** индивидуальный высокий чек.

Цена не должна определять весь возможный объём работы. Базовый scope должен быть ограничен.

---

## 3. Базовый scope

Нужно описывать не «работаю 1 час», а конкретный законченный результат.

Примеры модели:

### WordPress fix

База:
- одна небольшая правка/ошибка;
- один сайт;
- без разработки крупного нового модуля.

### Telegram notification

База:
- один источник события;
- отправка сообщения в один Telegram-чат/бот;
- базовое форматирование уведомления.

### Parser

База:
- один источник;
- ограниченный набор полей;
- выгрузка CSV/XLSX;
- без сложного обхода защиты и авторизации.

Главная задача scope — сделать входную покупку простой и не допустить бесконечного объёма за минимальную цену.

---

## 4. Структура описания — рабочая гипотеза

### Блок 1. Что получит клиент

2–4 строки без длинного рассказа о разработчике.

> Исправлю ошибку или внесу небольшую доработку на WordPress-сайте. Перед началом посмотрю задачу и скажу, входит ли она в базовый объём.

### Блок 2. Типовые задачи

Список конкретных примеров:
- форма не отправляет заявку;
- ошибка PHP/JS;
- мобильная версия;
- новый блок;
- интеграция webhook;
- уведомление Telegram.

### Блок 3. Что входит в базовую стоимость

Максимально конкретно.

### Блок 4. Что считается дополнительной работой

Новые страницы, сложная интеграция, несколько сайтов, большая логика, обход защиты и т. п.

### Блок 5. Что нужно от клиента

- URL;
- доступы при необходимости;
- описание проблемы;
- пример ожидаемого результата;
- документация/API, если есть.

### Блок 6. CTA

> Если не уверены, подходит ли задача под базовый кворк — напишите, я быстро оценю объём.

---

## 5. Дополнительные услуги

Финальный набор extras будет собран после отдельного исследования карточек. Уже сейчас логично тестировать:

- дополнительная задача/правка;
- срочное выполнение;
- дополнительная страница/источник;
- подключение API;
- база данных;
- авторизация;
- админка;
- deploy на сервер;
- документация;
- расширенная поддержка после сдачи.

Extras должны увеличивать чек, не разрушая понятную дешёвую точку входа.

---

## 6. Обложка

Пока не финализировать. Требуется отдельный визуальный анализ первой выдачи.

Рабочая гипотеза:
- один главный визуальный тезис;
- крупное понятное название результата;
- логотип платформы/сервиса только если он помогает мгновенно распознать услугу;
- без перегруженного списка технологий;
- визуально отличаться от соседних карточек.

---

## 7. Портфолио возле карточки

Карточка должна вести к максимально похожему кейсу.

Не «мой лучший проект вообще», а доказательство:

> клиент ищет Telegram + CRM → показать бот/интеграцию;

> клиент ищет CRM/кабинет → показать RuviCRM/Skillcue соответствующим углом;

> клиент ищет WordPress fix → показать конкретный before/after или пример доработки сайта.

---

## 8. Товарная матрица

Не объединять всё в один кворк. Разделять по намерению:

- WordPress fix
- WordPress доработка
- PHP/JS ошибка
- адаптив/CSS
- форма/заявка
- сайт → Telegram
- webhook/API
- CRM интеграция
- PHP script
- Python script
- parser → Excel
- n8n fix
- n8n automation
- Telegram bot fix
- Telegram bot с нуля
- Telegram + CRM/API
- VPS/Linux fix
- deploy/Docker
- AI integration

После первого заказа и расширения лимита кворков матрицу можно масштабировать значительно шире.
