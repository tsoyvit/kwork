# PROFILE_SPEC

Цель профиля — не заменить кворки и не пересказать резюме. Он должен снять вопрос: **«этому исполнителю можно доверить мою техническую задачу?»**

Следовательно, профиль можно делать широким. Конкретность обеспечивают кворки и портфолио.

## 1. Аватар

Приоритет:
1. нормальная фотография человека;
2. хороший контраст, лицо читается в маленьком размере;
3. без случайной буквы/заглушки.

У ряда сильных продавцов лицо повторяется и на covers, усиливая узнаваемость.

## 2. Профессиональный title

Не перечислять 10 технологий.

Формула:
`[тип результата/роли] + [2–4 главных класса задач]`

Варианты направления для нашего профиля:
- `Разработчик: сайты, боты, автоматизация и интеграции`;
- `Full-stack разработка, автоматизация, API и Telegram`;
- `Доработка сайтов, боты, API, CRM и автоматизация`.

Title широкий, но остаётся коммерчески понятным.

## 3. Первая фраза description

Сразу buyer-facing:

> Решаю технические задачи для бизнеса: от небольшой правки сайта или скрипта до Telegram-бота, интеграции, CRM и полноценного веб-сервиса.

Задача первой фразы — дать клиенту разрешение написать даже с нестандартной задачей.

## 4. Что описывать дальше

### Блок A — какие задачи берём

Не stack, а outcomes:
- сайты: исправления, доработки, функционал;
- Telegram / bots / Mini Apps;
- API и CRM integrations;
- automation и data processing;
- parsers/scripts;
- backend / admin panels / user cabinets;
- server/deploy tasks;
- AI integrations.

### Блок B — доказательство масштаба

Коротко:
- коммерческий production experience;
- полноценные собственные продукты;
- опыт CRM/automation/integration systems;
- умеем подключаться к существующему codebase, а не только делать с нуля.

Не превращать блок в хронологическое резюме.

### Блок C — как работаем

Пример логики:
`задача → уточнение результата → цена/scope → разработка → проверка → сдача`.

### Блок D — CTA

> Опишите задачу как есть. Если нужно — сам задам технические вопросы и предложу вариант реализации.

## 5. Stack

Стек размещать ниже, компактно, только как trust signal. Например:

`PHP/Laravel • Python • JavaScript • SQL • REST API • WordPress/Bitrix • Linux/Docker`

Не начинать profile description с технологий.

## 6. Ширина профиля

Не писать `делаю вообще всё` без доказательств. Ширина должна выглядеть как **единый класс прикладной IT-разработки**:

`сайты + программирование + автоматизация + integrations + bots + infrastructure`.

Mobile/game dev можно брать через Биржу при подходящей задаче, даже если они не стоят в headline.

## 7. Trust signals

До появления Kwork reviews trust строим через:
- сильный avatar;
- professional title;
- реальные screenshots портфолио;
- понятные product cases;
- конкретные kworks;
- быстрый ответ;
- понятные вопросы по задаче.

После появления заказов главный social proof постепенно переносится в Kwork metrics/reviews.

## 8. Чего не должно быть

- длинной биографии;
- перечисления каждой библиотеки;
- формулировки `начинающий`;
- акцента на том, что разработка делается с Codex;
- обещаний `сделаю абсолютно всё` без структуры;
- огромных полотен про работодателя.

Codex/AI — производственный рычаг, а продаётся результат.
